# Role-Based Mobile App Backend — Code-First Approach

## Question: Code First or Database First?

When building a **role-based mobile app**, the recommended approach is **Code First**.

### Why Code First?

| Concern | Code First ✅ | Database First |
|---|---|---|
| **Speed of iteration** | Change a Java class → schema updated automatically | Edit SQL script → regenerate code |
| **Single source of truth** | Entity class IS the schema | Schema and code can drift out of sync |
| **Refactoring** | Rename a field in one place | Update DB, then update code |
| **Version control** | Entities are in Git with your code | Schema files often live separately |
| **Team fit** | Developer-centric teams | DBA-centric teams |

**Code First with Hibernate is ideal for mobile app backends** because:
- The schema evolves as fast as new features are added.
- Spring Data JPA generates all the boilerplate SQL.
- In production, switch from `ddl-auto=update` to **Flyway** or **Liquibase** for reproducible, versioned migrations.

## Architecture

```
Mobile App (iOS / Android)
        │  HTTP + JWT Bearer token
        ▼
Spring Boot REST API
        │
        ├── /api/auth/register   ← create account
        ├── /api/auth/login      ← get JWT
        ├── /api/users           ← ROLE_ADMIN only
        ├── /api/users/{id}      ← ROLE_ADMIN / ROLE_MODERATOR
        ├── /api/content/public  ← any authenticated user
        ├── /api/content/moderated ← ROLE_ADMIN / ROLE_MODERATOR
        └── /api/content/admin   ← ROLE_ADMIN only
        │
        ▼
H2 / MySQL / PostgreSQL
(schema auto-generated from @Entity classes)
```

## Database Schema (auto-generated by Hibernate — Code First)

```sql
-- Generated from User.java, Role.java, Permission.java

CREATE TABLE permissions (
    id   BIGINT AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(60) NOT NULL UNIQUE
);

CREATE TABLE roles (
    id   BIGINT AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(30) NOT NULL UNIQUE   -- ROLE_ADMIN | ROLE_MODERATOR | ROLE_USER
);

CREATE TABLE role_permissions (
    role_id       BIGINT NOT NULL REFERENCES roles(id),
    permission_id BIGINT NOT NULL REFERENCES permissions(id),
    PRIMARY KEY (role_id, permission_id)
);

CREATE TABLE users (
    id       BIGINT AUTO_INCREMENT PRIMARY KEY,
    username VARCHAR(50)  NOT NULL UNIQUE,
    email    VARCHAR(100) NOT NULL UNIQUE,
    password VARCHAR(255) NOT NULL,
    enabled  BOOLEAN NOT NULL DEFAULT TRUE
);

CREATE TABLE user_roles (
    user_id BIGINT NOT NULL REFERENCES users(id),
    role_id BIGINT NOT NULL REFERENCES roles(id),
    PRIMARY KEY (user_id, role_id)
);
```

> **Note:** The SQL above is shown for documentation only.  
> With `spring.jpa.hibernate.ddl-auto=update` Hibernate creates it automatically.  
> In production use `ddl-auto=validate` and maintain the schema with Flyway.

## Default Roles & Permissions

| Role | Permissions |
|---|---|
| `ROLE_ADMIN` | READ_USERS, WRITE_USERS, DELETE_USERS, READ_CONTENT, WRITE_CONTENT |
| `ROLE_MODERATOR` | READ_USERS, READ_CONTENT, WRITE_CONTENT |
| `ROLE_USER` | READ_CONTENT |

## Running the Application

```bash
cd role-based-mobile-app
mvn spring-boot:run
```

- H2 console: <http://localhost:8080/h2-console>  
  JDBC URL: `jdbc:h2:mem:rbacdb`

## API Examples (curl)

### Register
```bash
curl -s -X POST http://localhost:8080/api/auth/register \
  -H "Content-Type: application/json" \
  -d '{"username":"alice","email":"alice@test.com","password":"alice123"}'
```

### Login
```bash
TOKEN=$(curl -s -X POST http://localhost:8080/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"admin123"}' | jq -r .token)
```

### Access protected endpoint
```bash
curl -H "Authorization: Bearer $TOKEN" http://localhost:8080/api/users
```
